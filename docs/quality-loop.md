# 质量控制回路（写完整本后暴露的问题 → 修法）

第一本《旧城换命》10 章 23,797 字跑完后，体检报了 **5 block / 23 warn**，过审只有 2/10，标题还出现「血契×6」。逐条修：

## 1. 时间线误报：按场景记录，不再按章

- 表 `timeline` 加 `scene` 列（老库自动迁移）。
- `addTimeline()` 支持 `scene`；抽取 prompt 要求每条时间线带 `scene`（同章换地点就写不同 scene）。
- `timelineIssues()` 改成**按 `章#scene` 分组**：同一场景里同一人出现在两地才算矛盾；不同场景是正常换场。
- 回归测试：`test/consistency.test.ts` 新增「不同场景换地点不算矛盾 / 同场景两地才算」。

## 2. 爆点必须有铺垫

- 规划 prompt 新增第 9 条：每个爆点写 `setup`（第几章埋的什么），强度≥4 没 setup 会被打回；第 10 条：自造的词必须当场给好处或代价。
- 规划输出 JSON 的 `highlights[]` 增加 `setup` 字段；抽取侧 `highlights[]` 增加 `setup_note`。
- 节奏页继续对"强度≥4 无铺垫"告警（`pacing.ts`）。

## 3. 标题去重

- 规划 prompt 第 8 条：列出已用标题，禁止重复意象。
- `ensurePlan()`：标题规范化后与已用标题重复、**或前两字相同**，就带"上一版标题已用过"再要一次。
- 仍重复则沿用原题并在事件流里提示。

## 4. 审稿模型独立（主写 8B、审稿换 GLM-4-9B）

- `NOVEL_FORGE_REVIEW_MODEL`：设置后 CLI/服务端会单独建一个审稿 LLM（temperature 0.3），`writeChapter` 的 review 走它。
- 不设则与主模型相同。

## 5. 审稿结果归一化（模型抄枚举/填 0 分）

GLM 当审稿人时，会把 `"severity":"block|warn"`、`"type":"continuity|voice|..."` 原样抄回来，分数填 0，导致所有章都判 revise。修法：

- `chapter.ts` 归一化：`severity` 只取 block/warn；`type` 从枚举里挑一个；`scores` 每项 clamp 到 1-10，缺失/0 记 7。
- verdict 由归一化结果重算：**有 block 或平均分 <7 才 revise**，否则 pass。
- 审稿 prompt 明确"不要照抄示例、分数别填 0、issues 最多 5 条"。

## 6. 章末钩子兜底

- 模型没标 hook 时，若最后一段是 ≤90 字的短动作句（且不含总结词），自动补记一条 hook 证据。
- 结尾像总结时，只重写最后一段成钩子（三种写法任选），带套话则丢弃。

## 7. 返工单调化

- 定点替换后，套话数没有下降就**回滚**，避免"越改越烂"。

## 验证

```bash
pnpm verify          # 57 个单测 + HTTP 链路
node scripts/run-book3.sh   # 3 章 A/B：写手 Qwen3-8B、审稿 GLM-4-9B
```

## 修复前后对比（真实跑书）

| 指标 | 修复前（《旧城换命》10 章） | 修复后（《雾锁铜城》3 章） |
| --- | --- | --- |
| 体检 block / warn | 5 / 23 | **1 / 1** |
| 时间线"同人两地"误报 | 大量（按章分组） | **0**（按场景分组） |
| 标题重复 | 血契×6 | 铜钱异变 / 裂纹中的名字 / 血契现形（无重复意象） |
| 审稿通过 | 2/10（审稿人=写手同模型） | **1/3**（审稿人 GLM-4-9B，均分 7.8 过；6.2/6.5 不过） |
| 章末钩子 | 9/10 | 3/3 |

剩下的是"章节质量分"问题：均分 6.2-6.5 的章会被审稿打回，这是闸门该做的事；要提高过审率要么加大返工轮次，要么换更强的写手（GLM-4-9B / Qwen3.8-27B）。

# 可读性专项（对话过多、剧情看不懂）

反馈：几章读下来"对话过多、剧情看不明白"。根因有两个：提示词把对白当硬指标（每 400 字 3 轮），以及没有"这一章到底讲了什么"的锚。

## 改动

1. **对白配额改成区间**：30%-40%，并禁止连续三句纯对白；对白前后必须有动作或环境。
2. **场景五拍**：①谁/在哪/要干什么 ②具体阻碍 ③各做一次动作或交换东西 ④结果变化（谁得/谁失）⑤留一个具体麻烦。
3. **剧情梗概先行**：`plan` 先输出 `synopsis`（3-5 句，谁→要做什么→遇阻→结果→留什么麻烦），落库到 `chapter_plans.synopsis`，写正文时整段注入，正文必须实现它。
4. **节拍要写 event**：每个 beat 一句话事件，禁止写氛围。
5. **每段 2-5 句**：禁止一句一段的碎句文（上一版 GLM 写成了一段一句）。
6. **审稿新增两条**：可复述性（说不出"谁为了什么做了什么、结果怎样"直接 block）；对白过量（连续三句纯对白或占比>60%）。
7. **质检新增**：`maxDialogueRun`（连续纯对白段数）与对白占比上限 55%。

## 验证结果（用百炼 qwen-flash 跑的一章）

硅基免费额度在写完第一本书后耗尽（`account balance is insufficient`），改用阿里百炼 `qwen-flash`：

- 1972 字，**质检 88，审稿 pass，状态 reviewed**
- 对白占比 10%，连续纯对白 0 段，章末钩子 ✅
- 梗概先行生效：正文按"拾到铜钱→沈砚白说它是活物→残图指向父亲旧案→通缉令上的名字没写完"这条线走，读者能复述
- 遗留：句子被切成一句一段（新加了 `oneSentenceRatio` 质检 + 提示词硬约束，下一章起生效）

顺带修了 JSON 截断问题：`Llm.json()` 默认给 2600 token，截断自动升额重试（之前 qwen-flash 的 plan JSON 被 1600 截断，整章白跑）。

## 验收口径

- 单章对白占比落在 15%-45%
- `maxDialogueRun` ≤ 2
- 审稿能通过"可复述性"这一条
- 人读第一段能说出：谁、在哪、要做什么

# 可读性专项 v2（2026-11-25，对话墙/场景瞬移）

上一轮“对白占 30%-40%”的配额仍会把模型推向对话墙；同时旧质检按引号字符算对白，
带“他说/她问”的段落会漏检，且没有检查地点锚点与环境密度。

## 本轮硬规则

1. **删除“每 400 字至少三句对白”**：默认文风改为叙述优先，动作/环境/物件推进占全章六到七成。
2. **含对白段落连续检测**：连续 4 段含对白直接 block；带叙述标签的对白不再漏检。
3. **叙述下限**：叙述字符低于 45% 直接 block；对白不能用“他说”包装成叙述蒙混过关。
4. **环境/物件密度**：每章至少按字数出现若干完整环境段，并统计具体物象/千字；不足直接 block。
5. **地点锚点**：场景第一段必须落到计划地点；换地点必须出现走路/推门/上车/拐巷等位移，否则场景重写。
6. **整章地点覆盖**：计划里的多个地点必须真的落地，不能只在同一张桌边换话题。
7. **失败不落垃圾稿**：真实 provider 场景重试后仍不合格，整章报错，不把坏正文存进数据库。
8. **定点返工判定修正**：不再只看套话数量；目标原文已改掉且质检不崩就保留，避免审稿指出的连续性硬伤被错误回滚。

## 真实模型小样

- 2,367 字，4 个场景，真实写到 4 个不同地点
- 对白字符占比 8%，叙述占比 92%
- 含对白段落 50%，最长连续 3 段（不再是对白墙）
- 环境/物件锚点 70.4 个/千字
- 场景 3 首次生成出现“从河汊瞬移到督察长办公室”，被新闸门打回并重写通过
- 初次 76 分 draft；审稿指出称重数字矛盾；定点返工后 **82 分 reviewed**

# 跨书同质化专项（2026-11-25）

问题：两本书案件不同，生成出来却像同一体系外传。

根因不是单一措辞，而是跨书共享了整套表达模板：

1. 所有书默认 `style_id=default`，文风手则完全相同。
2. 场景提示词里硬塞同一段“沈砚/老刀/茶碗/名单”范文。
3. 每章都强制“物件 must + 线索 + 爆点 + 钩子”，模型用同一套叙述动作套不同案子。

处理：

- 新增 `src/engine/voice.ts`：每本书生成独立 `voiceProfile`，包含 narrator/tone/diction/rhythm/dialogue/imagery/signature/avoid/sample。
- 生成声纹时把工作区其它书的标题、题材、前提、语气一起喂进去，并明确要求“不能写成同一体系外传”。
- 场景提示词删除全项目共用范文，只使用本书声纹与本书作者样本。
- 生成台展示“本书专属声纹”，可单本重生成；CLI 增加 `voice --book B [--regen]`。
- 换书时 `buildContext()` 自动载入对应声纹，规划、场景、审稿、段落返工全部使用同一本的声音。

实测：

- 《旧城换命》声纹：体力活/时间路程/“还剩”计量，禁止当铺铜钱玄学。
- 《雾锁铜城》声纹：警察“称重”习惯/错认搭档/鞋手细节，禁止民国氛围道具堆砌。
- 两本书各写 500 字样段，8-gram 重合率 **0**。

# 科技流可读性 v3（2026-11-25，去说明书腔）

反馈：科技流样段仍像设备巡检和技术讲解，读者不是来上课。

根因：

1. 声纹里的 terminology 虽允许专业词，但没有硬性上限。
2. 场景提示词里同时塞了太多写作要求，模型逐条“表演文风”。
3. 第一人称、现在时、短句断行等 signature 被用成了花活，产生刻意感。

处理：

- 场景提示词砍掉环境段、段落数、物件配额、对白段落配额等长清单，只保留：人物要什么、遇到什么、局面怎么变、读者不是来学知识、语言自然。
- 科技内容强制“后果优先”：能用“灯灭了/门打不开/时间少了三分钟”说清，就不解释设备、原理和术语。
- 每 500 字最多 1-2 个专业词/缩写，且必须立刻绑定动作、损失或代价。
- 新增技术术语质检：缩写/技术词密度过高直接 block；一句一段超过 60% 也直接 block。
- 声纹生成默认普通第三人称近景；第一人称/现在时/特殊格式只在题材强烈需要时使用。
- 明确禁止靠倒计时、一句一段、重复句、特殊排版表演风格。

实测《零号机房》新版 803 字样段：

- 技术缩写 **0**
- 技术词密度 **0/千字**
- 一句一段比例 **0**
- 质检 **94**
- 内容只写温度异常、重启提前四秒、本子被挪过，不再解释系统原理。
