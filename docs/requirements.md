# 需求卡 · draftvein

## 一句话目标
一个"逐章推进"的长篇小说生成框架：先立骨架，再一章一章写、一章一章记账（伏笔/事实/时间线），并把成品递交进作家助手。

## 真实使用者与场景（JTBD）
- 谁：写连载的网文作者（自己写不动或想让 AI 先出可用草稿）。
- 场景：每天要更新 1-3 章；需要草稿"能直接用"，而不是需要大改的模板文；需要在几十万字跨度里不忘伏笔、不崩人设。
- 设备：桌面为主（写作/审稿），手机上想能看进度与推章节。

## 必须做到（可测）
1. **不成批生成**：任何时刻，章节计划最多覆盖"已写章 + 1 章前瞻"（`ensureWindow` 保证，验收脚本断言 `maxPlan <= 已写+1`）。
2. **单章流水线**：规划 → 逐场景写 → 局部质检返工 → 拼装 → 字数校准 → 规则质检 → 模型审稿 → 定点返工 → 抽取记账 → 落库。
3. **伏笔台账证据化**：埋点/回收都必须带正文连续原句，抽不到就拒绝（`applyThreadEvents` 单元测试覆盖 4 种拒绝情形）。
4. **上下文分层**：每章只装配相关设定（关键词检索 top-N）、最近 6 章摘要、上一章尾部 900 字、到期线索、最近硬事实。
5. **质量闸门**：套话词表、段首重复、段落长度、对白字符占比、**含对白段落占比/最长连续段落**、叙述占比、环境物件密度、场景地点锚点、换场位移、章末总结句、跨章重复句；真实 provider 场景不合格直接拒绝落库。
6. **状态更新**：每章落库同时写 facts / timeline / threads，下一章规划读取到期线索（逾期线索会在生成前置顶提醒）。
7. **作家助手项目内直连**：工作台「递交」页扫码登录、显示二维码、拉取远端作品、绑定当前书 CBID、把本地章节写成草稿；默认不发布。登录模块/API/UI同属项目，不靠外挂脚本。
8. **可离线验收**：`DRAFTVEIN_PROVIDER=mock` 全链路可跑，`pnpm verify` 通过。
9. **跨书声纹隔离**：每本书根据书名/题材/前提/读者生成独立叙事声纹（叙述距离、语气、句法、对话、意象、signature、禁止项、原创样段），存进本书数据；场景提示词不再使用全项目共用固定范文。

## 明确不要
- 不要"一键生成 100 章"的批量模式。
- 不要在提示词里"祈祷"模型遵守规则——关键约束必须落在代码与校验里。
- 不要给作者做自动发布（除显式配置）。
- 不要假数据/假图表；控制台里每个数字来自数据库。

## 数据/流程/边界情况
- 数据：SQLite（`books / bible / arcs / chapter_plans / chapters / threads / facts / timeline / runs / events / llm_calls / pushes`）。
- 边界：LLM 超时/失败重试 3 次；JSON 抽取失败不影响已有正文；字数不足补收尾场景；线索证据不匹配拒绝并留痕。
- 断点：章节按 `(book_id, idx)` 唯一，可从任意章续写；`reviseOnly` 支持只返工。

## 结构（2026-11-24 追加，owner 明确要求）
1. 章节必须**先分卷再分章**显示；卷可新建/编辑，卷头显示章区间与字数汇总。
2. 大纲默认有**总纲 + 章纲**，可继续加其他纲（势力谱、金手指规则等）；章纲由章节计划自动汇总。
3. 角色默认分**主要角色 / 次要角色**，可新建其他角色分类。
4. 设定默认分**背景设定 / 其他设定**，可新建分类并在分类下新增设定。
5. 以上全部按书隔离，不跨本复用。

## 视觉方向
控制台，工具感，密度紧凑（表格行 34px），中性灰 + 单一点缀色（墨绿），等宽数字，无渐变/玻璃/发光；桌面三栏（书目 / 章节表 + 生成台），移动单列 + 底部 tab。

## 验收标准（逐条可测）
- `pnpm verify` 全绿（全量单测 + 真实 HTTP 链路）。
- `pnpm visual` 出桌面 1440×900 与移动 390×844 截图，console 无 error，无横向溢出。
- 台账页能看出"未回收/逾期/回收率/平均跨度"。
- 递交页未登录时能直接发起项目内扫码登录，并显示二维码/失败原因；不允许要求退出工作台手改 JSON。

## 风险与假设
- 假设：作者有阅文作家账号并能用微信完成一次扫码；不需要安装作家助手客户端。
- 风险：阅文接口随版本变化；已在 docs 记录抓取依据（5.24.0）。
- 假设：真实模型质量高于 mock；mock 只证明链路正确。
